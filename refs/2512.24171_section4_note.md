# Dudko 2512.24171 Section 4 - repo integration note

This note records how Section 4 of `refs/2512.24171.pdf` should be read against
the current `molecule-conjecture` codebase and planning stack.

## Relevant statements from the paper

The integration target is the Section 4 roadmap around the Near-Degenerate
Regime:

- **Problem 4.3**: establish pseudo-Siegel a priori bounds in the remaining
  unbounded satellite ql cases.
- **Interpolation Problem 4.4**: develop a Virtual Molecule version of the
  Near-Degenerate Regime.
- **Section 4.5**: virtual near-Molecule renormalization, where the first ql
  renormalization `f1` is primitive but the scales between the main Molecule `M`
  and a deeper satellite copy `M(n)` are not controlled by the puzzle levels of
  Section 4.2.

In Dudko's formulation there is a canonical satellite chain

`M = M(0) ⊋ M(1) ⊋ ... ⊋ M(n) ⊋ M(n+1)`

with two highlighted virtual-Molecule subcases:

- virtual bounded-type satellite ql (`n >> 1` with bounded relative periods),
- virtual near-neutral (`n = 0`).

The paper's intended conclusion is that Problem 4.3, Problem 4.4, and the
arguments of Sections 4.1-4.4 together should imply the full MLC.

## Current repo state

The current verified top-level frontier in this repo is still:

- `Molecule.molecule_h_norm`

That is what `make check` reports for `Molecule.molecule_conjecture_refined`.
So this paper note should be read as a **research-roadmap sidecar**, not as a
claim that the repo has already formalized the remaining satellite / virtual
Molecule cases.

## Mapping Dudko Problem 4.3 to current modules

### `Molecule/Problem4_3.lean`

This file already contains the formal interface for the current Problem 4.3
route:

- `PseudoSiegelAPrioriBoundsStatement`
- `FixedPointNormalizationData`
- `problem_4_3_bounds_established_of_fixed_point_data`
- `problem_4_3_bounds_established`

What this gives today:

- a Lean-facing statement that packages pseudo-Siegel bounds around a fixed
  point `f_star`,
- a localized fixed-point normalization interface,
- a theorem route from fixed-point data plus pseudo-Siegel/orbit hypotheses to
  the `PseudoSiegelAPrioriBoundsStatement`.

What it does **not** give today:

- a source specific to Dudko's remaining **unbounded satellite ql** cases,
- a formal distinction between bounded-type satellite, unbounded satellite, and
  near-neutral subregimes,
- a virtual-Molecule scale model.

So `Problem4_3.lean` is currently a theorem-shell interface, not a completed
formalization of Dudko Problem 4.3 in the paper's full scope.

### `Molecule/PseudoSiegelDisk.lean`

This file provides the pseudo-Siegel disk interface used by the current route:

- `IsQuasidisk`
- `PseudoInvariant`
- `construct_pseudo_siegel_disk`
- existence / openness / containment / invariance lemmas

Current role:

- isolates the pseudo-Siegel disk payload needed downstream,
- keeps the proof pipeline executable.

Current limitation:

- this is still an abstract interface layer; it does not encode the additional
  geometry Dudko needs for the remaining unbounded satellite cases.

### `Molecule/RenormalizationOrbit.lean`

This file packages the orbit-transport part of the current Problem 4.3 route:

- `renormalization_orbit_control`
- `renormalization_domain`
- `renormalization_orbit_lands_in_D`

Current role:

- expresses the return-time / landing-in-`D` transport obligations used by
  `Problem4_3.lean`.

Current limitation:

- it does not yet distinguish the different satellite combinatorics highlighted
  in Dudko Section 4, and it does not express virtual-Molecule first-return
  control.

### `Molecule/Conjecture.lean`

`Conjecture.lean` already has many residual seams around this route, including:

- `PseudoSiegelAPrioriBounds`
- localized fixed-data routes around `FixedPointNormalizationData`
- residual pseudo-Siegel / transport source interfaces

This means the repo has already done a large amount of **interface partitioning**
for Problem 4.3. The missing piece is not more wrapper decomposition by itself;
it is a genuine source that can justify the remaining Dudko-style cases without
falling back to the residual normalization axiom.

## What Section 4.5 adds that the repo does not yet express

The current code does not yet have native objects for:

- the satellite-copy chain `M(s)`,
- relative periods `M(s+1) rel M(s)`,
- the split between virtual bounded-type satellite and virtual near-neutral,
- partially invariant virtual Julia sets,
- orbit control through only finitely many first returns before reaching the
  already-controlled primitive scales.

That is the main planning value of Dudko Section 4.5 in this repo: it points to
the missing **intermediate scale model** between the current pseudo-Siegel /
orbit interfaces and a real non-axiomatic source for the remaining bounds.

## Practical interpretation for the repo

The correct reading of Section 4 in this repository is:

1. the current code already has a Problem 4.3-shaped interface,
2. the completed plan work mostly localized and decomposed that interface,
3. the remaining mathematical gap is broader than the current Lean shell,
4. the next planning layer should explicitly track Dudko's virtual-Molecule
   program as a sidecar to the active `molecule_h_norm` elimination frontier.

That is why the next repo-facing planning step after this note should be a new
`PLAN_93_*` synthesis roadmap rather than a rewrite of the existing active
tracker.
